# Controlled Experiment Design

## Primary revision-time experiment

The primary controlled experiment is a 2 × 3 × 2 × 5 design:

- two fixed input suites: `FULLSRC` and `FULLREQ`;
- three local models: Llama 3.2 3B Q4_K_S, GPT-OSS 20B MXFP4, and Qwen3-Coder 30B A3B Q3_K_L;
- two modes: partitioned Local Bulk and Controlled Local Parallel;
- five repeats per suite-model-mode cell.

This yields 12 design cells and 60 successful runs. Each suite contains eight scenarios and 64 test cases. Parallel evaluates all 2,016 unordered pairs. Bulk evaluates 32 adjacent two-case partitions and performs no cross-partition reconciliation.

The complete protocol is in `experiments/full_suite/experiment_design.md`. Fixed suite JSON files are in `experiments/full_suite/suites/`; input and suite hashes are in `environment/`.

## Run evidence

Every successful run is preserved beneath `results/full_suite/bulk/` or `results/full_suite/parallel/`. Run folders contain the available configuration, manifest, raw output, classified-pair, retained/removed case, metric, execution-log, and database-record evidence generated by the harness.

Protocol-development failures are not mixed with the successful-run corpus. Their exclusion is documented in the local release audit; they do not contribute to the manuscript statistics.

## Historical evidence

The paper also reports earlier Serial, Bulk, and Parallel observations. Those are mapped by `results/historical/` and the paper result map. Serial was not rerun during the 60-run controlled study.

## Human Oracle

Three evaluators labeled aligned optimizer decisions as Unique, Similar, or Unclear with `human_oracle/human_oracle_pyside6.py`. Analysis aligns the three exports, computes Fleiss kappa, pairwise Cohen kappa, Gwet AC1, consensus strata, and optimizer performance by consensus strength.
