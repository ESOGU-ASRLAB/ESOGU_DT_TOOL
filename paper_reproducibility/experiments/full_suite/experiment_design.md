# Controlled full suite experiment design

The experiment retains historical Serial evidence and does not create any new Serial record. New evidence consists of two fixed 64-case suites, three installed local models, two modes, and five repeats per cell: 2 x 3 x 2 x 5 = 60 successful runs.

The source-code suite is `FULLSRC`; the requirements suite is `FULLREQ`. Both were generated by `qwen/qwen3-coder-30b` and exported once from the two pre-existing database sessions listed in `suite_manifest.csv`. FULLSRC uses session `52083295-62a9-45f4-bd77-ad32cc2599c2` / record `69aacdd4d040c89c74b30991`; FULLREQ uses session `40b370ff-da15-46f2-ad96-692814082995` / record `69aaf214d040c89c74b30994`. Every case carries an artifact-scoped scenario identity and a stable case UID. Suite JSON and content hashes remain fixed across repeats. Here, complete means the entire selected 64-case generated suite, not exhaustive behavioural coverage of its source artifact. No separate selection rationale beyond using these fixed complete generated suites for the controlled revision study is recorded.

The local llama.cpp server uses the installed GGUF artifacts, GPU offload, an 8192-token per-request context budget, temperature 0.1, top-p 0.95, top-k 40, and a deterministic seed schedule beginning at 20261017. Unsupported parameters are explicitly recorded by the run configuration rather than inferred.

Partitioned local Bulk and Controlled Local Parallel share the same semantic criteria but not the same interaction structure. The former receives the complete 64-case suite and classifies 32 deterministic adjacent two-case groups without cross-partition reconciliation. The latter generates every unordered case pair, evaluates explicit binary decisions in local concurrent batches, and aggregates them with connected components.
